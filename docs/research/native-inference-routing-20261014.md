# Native inference routing research

Date: 2026-10-14. Target: rice-multi-models 0.6.4, commit `e5c62341986396e5dbf9c3ab2e41ad124532e4f6`; Claude Code 2.1.299. This note records research and implementation constraints, not a completed routing fix.

## Finding

Current supported mod hooks cover the normal main and subagent turn loop and calls other mods make through the mods API. They do not currently give rice-multi-models an authenticated, caller-owned interception point for every native inference request. The previous native runtime audit already proved that native compaction, native web tools and the automatic permission classifier bypass the exposed completion hooks. Those failures were not rerun for this research.

A verified Bun preload seam permits an in-process adapter before the native host starts. A real Claude Code 2.1.299 proof now intercepted the native compactor's authentic request, supplied an in-process fixture response, and completed native compaction successfully. This establishes a native protocol and bookkeeping seam without a listener, proxy, gateway or signed-binary edit. It requires a launcher. Direct provider transport, live summary quality, concurrent caller ownership and the remaining native paths still require implementation and evidence.

The full requirement remains direct calls to configured providers, with every main conversation, child, nested child and resumed child owning its selected provider and model family. A proxy, gateway, process-wide alias change or replacement summarizer does not satisfy that requirement.

## SDK and transport seams

The official [Agent SDK 0.3.299 package](https://registry.npmjs.org/@anthropic-ai/claude-agent-sdk/-/claude-agent-sdk-0.3.299.tgz) binds Claude Code 2.1.299. Its public `Options` supports `pathToClaudeCodeExecutable` and `spawnClaudeCodeProcess`. It exposes hooks and subprocess transport, not a custom native inference `fetch` option. Its `/core` entry is a smaller bundle of the same SDK client, not an importable in-process Claude Code host. The package README still explains resolving or extracting a native executable. Thus changing the application-side SDK client alone does not intercept the native child's network calls.

The SDK's [hooks guide](https://code.claude.com/docs/en/agent-sdk/hooks) documents tool and lifecycle hooks, including pre/post compaction and model switches. TypeScript classic hooks receive `agent_id` and `agent_type` where they run inside a child. Neither the hook list nor current published `Options` supplies a general request-response replacement boundary.

The official Anthropic TypeScript SDK does have an appropriate lower-level extension: constructor `fetch` and `middleware` options. Middleware wraps every HTTP attempt, including retries, and observes canonical Anthropic request shapes. See [client source at inspected revision](https://github.com/anthropics/anthropic-sdk-typescript/blob/2979ed5cef4b2f059b95af23e08728c01e588f86/src/client.ts). This is a feasible seam for a host integration that owns client construction. It is not currently reachable through the supported Claude Code mod contract. Caller identity and selected caller model still need to be supplied before the host crosses that seam.

## Bun preload and launch coverage

Bun's [standalone executable documentation](https://bun.com/docs/bundler/executables#runtime-arguments-via-bun-options) says compiled programs accept runtime flags through `BUN_OPTIONS`. Its [code-generation documentation](https://bun.com/docs/runtime/code-generation-from-strings#what-the-flag-does-not-cover) specifically states that `--preload` there loads a file before the embedded entrypoint. Giving `--preload` directly to the compiled executable instead passes it to the application as ordinary arguments. An absolute owned module path avoids dependence on the caller's working directory. This documented mechanism matches the integration owner's 2.1.299 startup probe.

The direct adapter can preload normal maintained JavaScript, preserve the original native fetch function for unrelated HTTP operations, and replace native inference responses using the configured provider's direct client. It must identify inference by a validated request contract and preserve cancellation, retry semantics and native response shapes. It must also prove whether native entitlement, model-availability and permission-classifier gates can reject routed work before fetch. An available fetch hook is not by itself proof that those earlier gates have been fixed.

The first owned native-compaction preload probe failed: exit 143 after its bounded deadline, no intercepted native requests, and no native-compaction success. Subsequent startup diagnostics established a setup error: JSON/double-quoted preload paths in `BUN_OPTIONS` did not load the module in the actual embedded runtime, even when the process exited successfully. The probe's missing preload receipt means that run does not prove a product transport failure. Use validated unquoted path transport or a separately proved argument parser; ordinary shell quoting and parsing inside `BUN_OPTIONS` are separate boundaries.

Independent static inspection nevertheless found a private transport selection that a correctly loaded adapter must account for. In the shipped 2.1.299 distribution, `K$` supplies a fetch wrapper built by `Ww`; its default transport `Ese` reaches `Pqn` through `kf`. `Pqn` reads current global fetch, compares its identity with a value captured when its module loaded, and selects a private fetch-session function while the identities match. A stable preload wrapper can itself become that captured default and therefore be bypassed. This source finding is not the explanation of the setup-failed probe.

That private function is built by `Qfo`: in a standalone executable it obtains a `Bun.FetchSession` from `e0o` and calls the session's bound `fetch`. It is not a node:https call, and the inspected executable had no actual assignment replacing global fetch after startup. Bun's [FetchSession reference](https://bun.com/reference/bun/FetchSession) documents separate connection pools and bound instance fetch methods. A preload must therefore cover this API too, or deliberately make request-time global fetch distinguishable from the captured default. Constructor/instance wrapping remains an alternative candidate; the corrected accessor proof follows.

The corrected proof used validated unquoted `BUN_OPTIONS` path transport and an accessor that gives each global fetch read a fresh wrapper identity. The receipt `native-preload-compaction-direct.json` records Claude Code 2.1.299, `preload.loaded: true`, exit 0 and successful native compaction. The intercepted native request named `codex/owned`, carried request class `compaction`, contained four messages and a system prompt, and requested streaming. No HTTP listener was used. The native host generated the compaction request and retained its ordinary transcript/bookkeeping behavior; the fixture answered that request in process.

This is an actual native request/response protocol proof. It does not certify a live provider transport or the quality of a real generated summary: the answer was a controlled stand-in response. Earlier setup-failed receipts remain retained failures. The corrected proof supplies a new native result rather than relabeling those attempts as successful.

The inspected embedded modules have SHA256 `d76b39883fce037a0e7880f788aba8839c72cb738e641c6cacd7038590c1fb35` (`Pqn` and default-fetch capture), `b1de1d0c66ac98ac9c526086ac150d274a305582bf4702fa4f93ff4b9a24544b` (`Qfo`) and `508cba215fda6868df7a05e5089978c6e74c9aaf65cc2f22cf18df27af2ee431` (`e0o` and its fetch-session store). They were inspected in memory from the official installed distribution; no source or binary patch was made.

Ownership remains a separate problem. The same distribution's `Hl()` creates a main-agent context. Native side queries call it, so they do not automatically inherit a child caller's identity. Explicit child-loop contexts can add a percent-encoded `x-claude-code-agent-id` header during native client construction; the hardcoded main side-query context omits it. A working fetch interception cannot infer an unidentified child's provider from that missing header. Correct asynchronous caller propagation must be proved independently.

### Worker correlation as a caller-context candidate

The shipped 2.1.299 hook-host implementation retains immutable RPC correlation even where the exposed completion event omits agent identity. Its native host posts a `dispatch` or `dispatch_stream` frame containing `id`, `event`, `payload` and `environments`. For a normal turn or tool event, `payload` contains the event's native agent/model fields. The Worker returns continuation requests on its main channel: `next` contains `id`, `nextId`, `argument` and optional floors; `next_pull` contains `id`, `nextId` and an initial `open` object with argument/floors.

API operations use a dedicated MessageChannel for each loaded plugin environment. The Worker posts an `op` frame with `opId`, `dispatchId`, `registration`, `serving`, `rootEvent`, `op` and `args`. Streaming `op_pull` carries `opId` and an initial `open` containing the same operation metadata. The host links each environment's channel when it sends `load` with `environmentId`, plugin arguments and the transferred port. The host listener reads these frames through `MessagePort.onmessage`; the main Worker listener uses `addEventListener('message', ...)`.

Native `Hfn` looks up `inFlight[id]` and calls that dispatch's stored continuation. `jfn` similarly resumes the stream stored under the dispatch and `nextId`. Native `rpn` evaluates the named host API operation while handling the plugin channel's incoming frame. These are concrete callback boundaries where a preload can run its own AsyncLocalStorage context without modifying the native message payload or reconstructing caller identity from timing.

Proposed implementation: observe outgoing dispatches, bind a frozen caller context to the tuple of actual Worker object and dispatch ID, associate each transferred MessageChannel with that Worker/environment, then wrap the matching incoming callback under that exact context. Operations resolve `dispatchId`; next requests resolve `id`. When a host API call raises a nested completion dispatch with no agent field, that outgoing dispatch should inherit the already captured caller context rather than reinterpret its requested auxiliary model as the owner's model. An explicit normal-loop identity takes precedence when the native event defines one. New Worker instances must get a new map even when numeric IDs repeat.

Custom API nouns have a separate direct-call frame: `call` carries `callId`, `environmentId`, `call` and `callers`. A subsequent operation may carry that `callId` under `serving` instead of a dispatch ID. A direct caller context can be captured when that outgoing frame is posted, but generic shared queues and loaned work are not evidence that every later call belongs to that same conversation. The native host validates whether a plugin environment belongs to the active dispatch or serving call before constructing its caller facts. The adapter should preserve equivalent membership and lifecycle checks, not accept any matching number from an unrelated port.

This is an inference about a viable integration seam, not a published mod contract or completed concurrency proof. Async generator resumption, nested hooks, aborts, unloads, reloaded Workers, streamed RPC operations and overlapping children must be exercised. Missing or expired correlation must refuse unidentified routed inference. Timer or interface operations with no dispatch ID cannot be assigned to whichever child ran most recently. Preserve native registration/serving semantics rather than assuming every such call has a conversation owner.

The official Agent SDK's current `Options.env` passes a supplied environment to the native subprocess; when supplied it replaces rather than merges the ambient environment. A caller must preserve the needed inherited environment while adding the preload. The existing `pathToClaudeCodeExecutable` or `spawnClaudeCodeProcess` can select an explicit launcher. The SDK does not need to become a gateway for this launch arrangement. [Official package declaration](https://registry.npmjs.org/@anthropic-ai/claude-agent-sdk/-/claude-agent-sdk-0.3.299.tgz).

Claude Code's documented [corporate launcher contract](https://code.claude.com/docs/en/corporate-launcher) supplies `CLAUDE_CODE_PROCESS_WRAPPER` or `processWrapper` for the background supervisor, agent-view sessions, update relaunches, Remote Control processes and split-pane teammates. It excludes the initial terminal launch, initial deep link, worktree/tmux relaunch and browser native-messaging process. Windows ignores that wrapper contract. Initial launch must therefore explicitly use the owned launcher; background launch coverage requires its own verified configuration. Preserve the managed native symlink. Setting a runtime preload variable only after the host is already running cannot preload that same process retroactively.

Preload proof must cover every supported execution platform and actual launcher path. Native CLI startup, native inference interception, correct concurrent caller ownership, subprocess propagation and desktop or IDE launch behavior are separate claims. Unsupported or uninstrumented hosts must not silently fall back to Claude inference.

## Feasible implementation contract

The following is a proposed integration contract inferred from the API and runtime evidence. It is not an existing Anthropic API.

1. Introduce a host request boundary immediately before every native model transport, using the preload seam if its native proof succeeds. Carry immutable session/agent ownership, the selected loop model, the native request's requested model, a purpose such as compaction/classification/web extraction, the complete native request, cancellation and timeout semantics.
2. Resolve the exact routed request when one is explicit. Otherwise resolve native auxiliary aliases within the owner's configured provider/family. Never infer ownership from the most recently active child, the main model, a prompt string, or a process-wide environment variable.
3. Use the existing direct provider adapters. Return a response in the native contract, including streaming chunks, tool calls, usage and failure information. Keep compaction prompts, transcript construction, summary integration, permission rules, native tool bookkeeping and cancellation in the host.
4. Invoke the boundary before constructing or authenticating an Anthropic client for routed inference, so an exhausted Claude subscription cannot block a request destined for another provider. Keep provider discovery/authentication distinct from inference.
5. Add caller ownership to `model.complete`, `model.classify` and child-aware fork operations, or expose a documented immutable caller context accessible from those operations. A companion noun is useful for cooperating mods, but cannot repair unidentified native or third-party calls by itself.
6. Bind capability support explicitly. Anthropic server web tools or advisor operations are not automatically present on every provider. A provider adapter must implement the requested capability directly or report an unsupported capability before any request goes to the wrong provider. A successful ordinary text request does not certify web search or every server tool.
7. Version-gate the host integration. On an unsupported host, retain a clear refused result for paths that cannot be routed safely. Disabling compaction or substituting a custom compactor is not acceptance for authentic compaction.

Proof must exercise actual native entry points with Anthropic inference denied, separate provider observations, overlapping children from different providers, explicit provider errors, aborts, retries and native compaction state. Deterministic provider fixtures establish routing and host contracts; live provider checks establish each configured provider's entitlement and actual capability. The final claim must retain those distinct scopes.

## Unknowns and next decision

Public docs and official distribution inspection did not establish a supported global native mod request hook. The known native failures, plus separate embedded native SDK request call sites, make merely adding another `model.complete` handler insufficient. Bun's preload mechanism gives a documented runtime entrypoint, with actual 2.1.299 native-compaction protocol proof, for a separate direct in-process adapter. Live provider transport, other native paths and ownership correctness through that entrypoint still need implementation proof. No installed binary, user settings or original live session was changed by this research.

The next implementation action is to build the direct adapter and immutable caller propagation around the proved preload seam, then exercise the native entry points against real adapters and overlapping children. Keep the shared request boundary and ownership propagation in one integration rather than reproducing every native subsystem in the mod. The solution's launch requirement must be explicit. Until the remaining required proofs pass, the mod alone cannot honestly certify the complete all-provider requirement.

OpenAI strict structured output has a narrower schema contract than arbitrary JSON Schema: the root is an object without root anyOf; objects declare `additionalProperties: false`; defined properties are required, with nullable types used to represent optional values. Setting strict true on an unmodified native schema does not make that schema compatible. Translate without changing its accepted meaning, or explicitly reject an incompatible contract before provider I/O. [Strict schema restrictions](https://developers.openai.com/api/docs/guides/structured-outputs#supported-schemas).

The source check found several acceptance requirements needing explicit coverage:

- Unsupported stop sequences or native caps must not disappear during Responses/Codex translation. Codex's subscription transport deliberately omits an unsupported backend cap, so the ordinary Responses API capability must not be assumed for that endpoint.
- Validate zero/cache-only requests separately, empty stop strings, named choices against declared tools, and boolean parallel suppression. Every effective cap should be bounded by the native request, model ceiling and any lower configured provider cap.
- Gemini/BEDROCK parallel suppression and Bedrock none need a capability decision or enforcement at the native response boundary. Silently allowing additional calls is not equivalent to the original native request. Dropping Bedrock tool definitions also requires checking transcripts that already contain tool-use history.
- Preserve provider configuration unrelated to the native override. Gemini's MIME/schema override must remove mutually exclusive schema settings while retaining other tool configuration. Strict schema compatibility must cover the schemas actually generated by native permission and hook evaluators.

Bun's global fetch function has a documented static `preconnect` property. A fresh bound-function getter loses that property unless it is forwarded. FetchSession's bound fetch intentionally has no preconnect. Preserve the original global function's required static behavior while retaining the changed identity needed for interception. [Bun fetch and sessions](https://bun.com/docs/runtime/networking/fetch#preconnect-to-a-host).

Preload inheritance requires the child's actual environment to retain BUN_OPTIONS. [Bun subprocess configuration](https://bun.com/docs/runtime/child-process) accepts an explicit environment. Shipped Claude Code 2.1.299 constructs background-process environments through a pre-settings environment snapshot, then removes selected session/provider/plugin fields. Inspection found no explicit BUN_OPTIONS removal in that builder, but this is not live inheritance proof. A child starts a fresh runtime; verify its own activation receipt and independently selected model. The public [corporate launcher contract](https://code.claude.com/docs/en/corporate-launcher) supplies the covered launch paths and exclusions, not proof that an already running background service has refreshed its environment.
