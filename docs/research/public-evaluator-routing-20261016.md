# Public evaluator routing and conversation ownership

Date: 2026-10-16. Inspected official native Claude Code 2.1.301, macOS arm64.

The supported `classic.Stop` and `classic.SubagentStop` events provide a usable replacement boundary for configured evaluator work. A replacement can keep the conversation owner from that enclosing event, execute prompt evaluation through its selected provider, and run a real native verification agent with native tools. This is different from trying to intercept every internal Anthropic SDK request. The official middleware contract permits returning a result in place of the native implementation; doing so also skips later handlers, so their obligations must be preserved explicitly. [Official mod event middleware](https://code.claude.com/docs/en/plugins/mods/events#answer-an-event)

## Auxiliary calls do not retain an observable child identity

An ordinary, isolated native process created two real concurrent children, with different routed model IDs. An outer observer intercepted their public `model.complete`, `model.classify` and `model.fork` calls and answered synthetically. No provider requests occurred.

Across eight calls:

- Complete input contained `model,prompt`; classify contained `text,labels,options`; fork contained `prompt`.
- `next.origin` identified the calling plugin, not its child.
- `$.session.model()` returned the main model.
- The auxiliary signal was neither live child's `turn.step` signal.
- A registered, deferred metadata tool, called inside each auxiliary handler and answered before its own implementation, received `agentId: undefined` on every call.

Receipt: `public-owner-context-tool-string.json`, SHA256 `016c34565bf04d0298b8804d2a89884b71c1396b28651f80c8215ac5da795918`. Native PID 47443 exited 0. The earlier metadata-tool attempt returned an object where a registered tool requires text/content; that was a fixture-shape failure and is not ownership evidence.

This establishes a missing owner field in these inspected dispatches. It does not establish that mods cannot replace useful behavior through other events. A routed auxiliary request whose owner is ambiguous must not silently select the main provider. Cooperating callers can pass an explicit owner through a separate supported contract; uncooperative calls still require a host owner field or another proven seam.

## The agent handback has an additional native classifier boundary

A normal registered native agent requires `SubagentHandback` in this build. Its tool implementation declares `classifierOnly() -> {onBlock: "flag"}`. A selected-provider `tool.check` allow eliminates the native classifier request, but the native handback rejects a hook-produced allow because it lacks native classifier provenance:

> Only the auto-mode classifier can allow SubagentHandback

The full controlled error also states that a hook allow is not the classifier's verdict. It returned `isError: true`. The agent subsequently reaching its maximum-turn limit must not be counted as successful handback delivery.

Receipt: `public-stop-production-handback-string.log`, SHA256 `2b6745e27ac9825f9bdd668c4c443e23bfbd9137f50dc6dfcd7393c4d88a4d87`. This used the current production permission hooks, their metadata command and a freshly built helper. It preserved native Read rules and observed selected-provider Agent/handback judgments. It does not prove the native handback accepts that replacement classification.

## Proven replacement for the final evaluator report

The evaluator owner can consume a strict final verdict from its exact child's `turn.step`, before returning control to native handback processing. It then invokes the real `TaskStop` tool for the exact agent ID it created. This deliberately terminates the owned verification task after its logical result is complete. It does not fabricate native classifier provenance or claim natural handback completion.

The isolated proof ran two ordinary native processes, PIDs 90651 and 90805, both exit 0. Each evaluator used two selected-provider steps: a real Read call, then a final verdict after receiving its actual tool result. Native permission checks ran for Agent, Read and TaskStop. The TaskStop result named the same created agent ID. One Stop allowed completion; a false prompt verdict caused another main turn. The Anthropic endpoint was an exhausted sentinel and received zero requests. No preload, launcher, real account or proxy was involved.

Evidence: `public-stop-owned-termination.log` and `public-stop-owned-termination.json`. The maintained production-copy acceptance is `scripts/proof-public-evaluators.mjs`.

## Required behavior for the maintained adapter

The planner and executor live in `hooks/evaluators.ts`; the public host adapter lives in `hooks/evaluator-runtime.ts`. The private bounded rendezvous and configured command runner live in `scripts/evaluator-wait.mjs`.

The native contracts require parallel matching hooks, settings-copy deduplication, independent plugin/skill copies, per-hook deadlines, and exact event substitution for `$ARGUMENTS`. Stop false verdicts continue the conversation; prompt `impossible: true` permits stopping, whereas agent verdicts ignore that field. Command hooks have exec and shell forms and their own failure policy. These details follow the [official hook handler and evaluator contracts](https://code.claude.com/docs/en/hooks#hook-handler-fields).

The adapter must read the effective merged settings. A raw source snapshot can expose disabled user or project configuration and must not be used as permission to run its commands. Managed groups already executed above the mod are excluded. Additional plugin, skill and agent definitions need actual loaded metadata, with their owning roots and lifetimes. A merged settings snapshot does not contain that complete inventory. Unknown handler kinds and background scheduling obligations are explicit unresolved behavior, never silently dropped or replayed through native inference.

Native agent tool filtering is not a general read-only filter. In this binary, `_2r` excludes StructuredOutput, Agent/Task, Poll and the native `Pct` control pool. That pool includes planning, interactive setup, scheduling, goal, publishing, conversation-ending and memory tools. `Q1n`'s coordinator Bash condition is disabled by literal `Men() -> false` in this inspected build. `qOt` additionally filters account-memory tools using private MCP metadata. The public tool list does not expose that metadata. Execution remains under native child permission rules; matching the private prompt visibility condition remains a specific metadata gap, not grounds to invent a broad ban on Bash or ordinary file tools.

The host adapter's selected-provider callbacks receive data and a statically bound helper port. The native authoring analyzer rejected passing the entire `$` object to a dynamic callback. The runtime therefore binds literal public API calls itself, while the integration owner supplies selected model resolution, approved configuration and normal helper response collection.

## Loaded evaluator sources

`hooks/evaluator-sources.ts` observes actual `agent.register` acceptance. The successful engine/core trace entry's `received` field contains the final definition after lower mods rewrite it; the registration hook's original input does not attest that definition. The collector keys its snapshot by the exact native returned type. A takeover returning a type without a successful core registration produces a scoped unknown-source diagnostic, rather than inventing its prompt or hooks. The runtime checks source errors before allowing a no-visible-evaluator fallthrough.

An isolated ordinary 2.1.301 process, PID 48150 exit 0, qualified that collector with no preload or HTTP requests. A lower mod changed both the prompt and evaluator hooks; the production collector returned the final hook. A separate takeover had no engine/core trace entry and produced no guessed hooks. The maintained proof is `scripts/proof-public-evaluator-sources.mjs`; its receipt is `public-evaluator-sources-split-registration.log`, SHA256 `948cdb40e2ab1ada9a1fee0e50fec15c2e5ad79c784552201a4372d79006d902`. The collector SHA256 is `449f04c7b1237a29d75b0783fa75da8e88b0d09b1d30e09624f508591cff75ac`.

That proof also establishes a remaining public inventory boundary. An enabled classic-only plugin ran its SessionStart command, but emitted no `plugin.register`. A mixed module/classic plugin emitted the module admission event, carrying name, root and scanned uses, without its loaded hook configuration. The effective settings object was empty despite both plugins and an invoked skill having Stop hooks. The documented admission event describes one hooks module, not every enabled classic-hook plugin. [Plugin admission reference](https://code.claude.com/docs/en/plugins/mods/reference#events)

`skill.prompt` exposes the invoked skill's path and raw frontmatter, including hooks. Those declarations are not the effective policy grants. The native implementation registers skill hooks conditionally, records their owning root, and removes `once` hooks using callbacks in its private session registry. Replaying raw frontmatter would therefore risk executing skipped hooks or repeating one-shot work. The collector does not claim that raw snapshot is a complete active-hook inventory. The official contract gives skills session lifetime and agent definitions their own run lifetime. [Hook source lifetimes](https://code.claude.com/docs/en/hooks#hook-locations)

For a registered child, authored Stop hooks are mapped to SubagentStop, as the native frontmatter contract specifies. Simultaneously authored Stop and SubagentStop are explicitly unqualified until their native ordering is bound. Agent-file or flag-defined types that never pass through public registration, and classic-only plugin/active skill registry coverage, remain named gaps. No universal source attestation is invented, and no blanket refusal is imposed on unrelated sessions. [Agent hook scope and Stop conversion](https://code.claude.com/docs/en/sub-agents#hooks-in-subagent-frontmatter)

SubagentStop matching now preserves native exact-name/list parsing for its simple alphabet; regex syntax remains regex. The focused suite covers exact names, comma/pipe lists, substrings, explicit regex and wildcard behavior.
