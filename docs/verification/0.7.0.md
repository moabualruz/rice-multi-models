# Native inference verification for 0.7.0

The supported host is the official compiled Claude Code 2.1.299 executable.
The adapter runs inside that executable, with no inference listener, proxy or
gateway. Node 22+ launches and verifies the bundled native preload. The official
executable and updater remain intact.

## Reproducible coverage

`npm run check` is the canonical gate. The local assembled run passed 367
contributor tests, 21 compiled Node tests, three native lifecycle tests, the clean
consumer payload proof, legacy routing proof, native adapter proof and isolated
launcher proof. GitHub CI runs this same gate on Ubuntu with pinned Node 22,
Bun and Claude Code.

| Behavior | Evidence |
| --- | --- |
| Native main and child loops | Real native processes and two overlapping children with distinct direct providers. Auxiliary completions, classifications and forks retain each child owner. |
| Skills and tool discovery | Native plugin-authoring Skill, ToolSearch, temporary Haiku skill alias and an explicitly alternate-provider forked skill. |
| Native web inference | WebFetch extraction and WebSearch retrieval/summary through the selected owner, including allowed-domain filtering. |
| Permission classifier | Native auto-mode classification allows and executes an owned read-only command; no permission bypass is used. |
| Evaluators | Actual prompt and agent Stop hooks return native structured decisions through the selected provider. |
| Compaction | Authentic manual compaction through all five API protocols; automatic compaction produces native transcript boundaries. |
| Resume/startup | UUID resumes retain the saved primary selection before hooks start. Automatic compaction uses saved approval grants without requiring a previous process snapshot. |
| Input bounds | A real local model-list endpoint and a configured 512-token input limit prove rejection before provider inference. |
| Failure and cancellation | A partial native stream fails after one provider request without native replay or provider fallback. Unit and compiled-runtime tests cover aborts, deadlines, accounting-only stream progress and retry contracts. |
| Provider protocols | Chat Completions, Responses, Anthropic Messages, Gemini and Bedrock use their direct clients inside the native runtime. Native credentials are not forwarded. |
| Installation mechanics | An isolated home verifies path spaces, protection of unrelated launcher files and resolution of a new plugin cache path after an update. |

Native integration fixtures deny the host's Anthropic inference endpoint and
observe the selected direct providers independently. Provider listeners are test
fixtures only. Model inventory uses actual local HTTP endpoints, not interception
of a helper process result. These checks prove routing and native contracts;
they do not establish commercial model entitlement or available quota.

## Live evidence

A separate owned session used live `codex/gpt-6.1-sol` while the native Anthropic
endpoint was unavailable. Seed, native `/compact` and follow-up all exited
successfully. The follow-up retained the controlled project name, port and Codex
provider constraint. No original user session was modified.

## Scope

The request boundary covers native Messages inference independently of request
class, including background and lifecycle calls. Immutable Worker/operation
correlation and native caller headers distinguish owners; an exact routed native
subagent request also preserves forked-skill ownership when its async caller is
the parent. Optional titles, goals, scheduling and precomputed compaction use
this shared boundary, rather than separate provider-specific dispatch code.
The table records the actual activated native smoke checks; it does not imply
that every optional UI feature was independently activated.

Full native coverage requires a verified launch through `rice-claude`. An already
running host cannot preload the adapter. Other native versions and native Windows
are not qualified. WebSearch requires a SearXNG JSON retrieval endpoint. Model
capabilities, credentials and entitlement belong to the selected provider.

Installation is a separate step after publication.
